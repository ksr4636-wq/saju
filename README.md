# 사주 만세력

한국천문연구원 검증 절기 데이터로 계산하는 사주 만세력 웹앱.
빌드 도구 없이 정적 파일만으로 동작합니다.

- 사주 원국(연·월·일·시주) 계산
- **라이트 분석** — 견종 캐릭터, 캐릭터 유형, 능력치, 상황별 반응
- **고전 명리 분석** — 격국·용신·조후·기세 (자평진전 / 궁통보감 / 적천수)
- 대운 9구간 개별 해석
- 여러 명 궁합 비교
- **럭키 가이드** — 오늘의 일진과 대조해 GO / STOP 판정

---

## 1. 배포 (GitHub Pages)

### 1-1. 저장소 만들기

GitHub에서 새 저장소를 만들고(예: `saju`), 이 폴더 내용을 올립니다.

```bash
cd saju-web
git init
git add .
git commit -m "사주 만세력 초기 커밋"
git branch -M main
git remote add origin https://github.com/<내계정>/saju.git
git push -u origin main
```

### 1-2. Pages 켜기

저장소 > **Settings** > **Pages**

- Source: **Deploy from a branch**
- Branch: **main**, 폴더: **/ (root)**
- Save

1~2분 뒤 `https://<내계정>.github.io/saju/` 에서 열립니다.

이 상태로도 앱은 완전히 동작합니다. 저장은 그 브라우저에만 됩니다.
여러 기기에서 같은 목록을 보려면 아래 Supabase 설정을 이어서 하세요.

## 2. Supabase 연결 (선택)

### 2-1. 테이블 만들기

Supabase 대시보드 > **SQL Editor** > New query
→ `supabase/schema.sql` 내용을 통째로 붙여넣고 **Run**

실행 후 아래 쿼리로 확인합니다. `rowsecurity`가 `true`, 정책이 4개여야 합니다.

```sql
select relname, relrowsecurity from pg_class where relname = 'people';
select policyname, cmd from pg_policies where tablename = 'people';
```

### 2-2. 키 넣기

대시보드 > **Project Settings** > **API** 에서 두 값을 복사해
`config.js`에 넣습니다.

```js
window.SAJU_CONFIG = {
  SUPABASE_URL:  "https://xxxxxxxx.supabase.co",
  SUPABASE_ANON: "eyJhbGciOi...",
  ENABLE_EMAIL_LOGIN: true,
  ENABLE_ANON_LOGIN: false
};
```

> **anon 키는 공개되어도 됩니다.** 브라우저에서 쓰라고 만든 키이고,
> GitHub Pages 같은 정적 호스팅에서는 숨길 방법도 없습니다.
> 대신 위 2-1의 RLS가 반드시 켜져 있어야 합니다.
>
> **service_role(secret) 키는 절대 넣지 마세요.** 이 키는 RLS를 무시합니다.

### 2-3. 로그인 방식 설정

대시보드 > **Authentication** > **Sign In / Providers** > **Email**

- **Confirm email**: 개인용이라면 **끄는 것을 권장**합니다.
  켜두면 가입 후 메일의 확인 링크를 눌러야만 로그인됩니다.
  Supabase 기본 메일은 발송 한도가 낮아 번거로울 수 있습니다.

대시보드 > **Authentication** > **URL Configuration**

- Site URL: `https://<내계정>.github.io/saju/`
- Redirect URLs에도 같은 주소를 추가

비밀번호 재설정 메일을 쓰려면 이 설정이 필요합니다.

### 2-4. 사용 방법

화면 위쪽 바에 이메일과 비밀번호(6자 이상)를 넣고 **로그인 · 가입**을 누릅니다.
처음 보는 이메일이면 계정이 자동으로 만들어지고 바로 로그인됩니다.

로그인 전에 저장한 기록이 있으면 **이 브라우저 기록 옮기기** 버튼으로
계정에 한 번에 옮길 수 있습니다.

로그인 상태는 브라우저에 유지되므로, 창을 닫았다 다시 열어도 그대로입니다.

## 3. 로컬에서 실행

`file://`로 열면 브라우저 보안 정책 때문에 일부 기능이 막힙니다.
간단한 서버를 띄우세요.

```bash
python3 -m http.server 8000
# http://localhost:8000
```

Supabase 로그인을 로컬에서도 테스트하려면
Redirect URLs에 `http://localhost:8000` 을 추가해야 합니다.

## 5. 계산 근거와 검증

| 항목 | 방법 | 결과 |
|---|---|---|
| 일주 | 율리우스적일 기반 60갑자, `(JDN + 49) % 60` | 한국천문연구원 음양력 API 실측값 4건(1391~2023년) 일치 |
| 절기 | 태양 시황경으로 12절 절입시각 사전 계산 | 2025년 24절기 절입시각표와 12절 전부 일치 |
| 엔진 이식 | Python 원본 대비 JavaScript 무작위 400건 교차검증 | 사주·대운수 불일치 0건 |
| 표준시 | IANA tzdata의 Asia/Seoul 이력 | 1908·1912·1954·1961년 변경, 서머타임 3개 기간 반영 |

- 월주 천간: 오호둔법 / 시주 천간: 오서둔법
- 연주 경계: 입춘(태양 황경 315°) 절입 시각

### 유파에 따라 달라지는 부분

- **진태양시 보정** — 서울 기준 약 −32분. 쓰지 않는 유파도 있어 옵션으로 두었습니다.
- **자시 처리** — 야자시설(일진은 자정 변경) / 정자시설(23시부터 익일)
- **대운수 반올림** — 3일=1년 기준의 반올림. 절상·절사 규칙이 유파마다 다릅니다.
- **지지 십성** — 지장간 본기만 반영한 단순화 값입니다.

절입 시각이나 시진 경계에 가까운 출생이면 화면에 경고가 뜹니다.
그 경우 출생 기록을 다시 확인하세요.

### 해석 체계

| 영역 | 근거 | 구현 |
|---|---|---|
| 격국(格局) | 《자평진전》 | 월지 지장간의 투간 여부로 격을 정하고, 사길신은 순용·사흉신은 역용 원칙으로 성격(成格)·파격(破格)을 판정 |
| 조후(調候) | 《궁통보감》 | 월지의 계절과 원국의 한난조습 지수로 조후용신 도출 |
| 기세(氣勢) | 《적천수》 | 득령·득지·득세 세 요소와 통관(通關) 여부로 일간의 강약 판정 |
| 용신(用神) | 억부론 | 기세 판정에 따라 억(抑)할지 부(扶)할지 결정 |

- 지장간은 월률분야 표준을 따랐습니다. 신(申)의 여기를 무(戊)로 볼지 기(己)로 볼지는 유파 차이가 있습니다.
- 양인(羊刃)은 양간에만 적용했습니다. 음간 양인은 유파에 따라 인정 여부가 갈립니다.
- 월지 정기가 투출하지 않고 중기·여기가 투출한 경우, 투출한 것으로 격을 정하되 월령 정기격을 겸격으로 병기했습니다.
- **신살(神煞)은 길흉의 근거로 쓰지 않습니다.** 궁합의 원진(怨嗔)만 보조 참고로 표시하며 가중치를 최소화했습니다.

해석 출력은 1) 성격과 심리적 기저 2) 사회적 역량과 성취 방향 3) 환경적 조언
4) 주체적인 삶을 위한 제언 순으로 구성됩니다.

### 라이트 분석

고전 분석과 **같은 원국·격국·기세 판정값**에서 문구를 도출하므로 두 결과가 어긋나지 않습니다.
비유만 바꾼 것이지 별도의 계산 체계가 아닙니다.

| 요소 | 근거 |
|---|---|
| 견종 캐릭터 | 일간(日干) 10종의 물상에 기질이 대응하는 실제 견종을 배정. 피규어 이미지는 `img/dogs/`에 WebP로 담겨 있고(10종 합계 약 69KB), 테두리 색은 일간의 오행 색을 씁니다. 이미지 로드가 실패하면 인라인 SVG 캐릭터로 자동 대체되므로 그림이 비는 일은 없습니다 |
| 캐릭터 유형 | 격국 10종에 장르별 인물 아키타입을 배정. 일러스트는 인라인 SVG이며, `img/arche/`에 피규어 사진을 넣으면 자동으로 그쪽을 씁니다 |
| 캐릭터 예시 | 각 아키타입마다 널리 알려진 영화·드라마 배역 3개를 **이름과 작품명 텍스트로만** 표시합니다. 이미지는 사용하지 않습니다 |
| 능력치 | 원국의 오행 개수를 목=추진력, 화=표현력, 토=안정감, 금=결단력, 수=통찰력으로 환산 |
| 상황별 반응 | 일간의 물상에서 도출한 행동 예시 |
| 궁합 라이트 | 두 사람의 일간 견종 조합 + 합충 유형별 상황 예시 |

캐릭터 유형 자체는 특정 작품의 인물이 아니라 **장르 아키타입**입니다.
그 아래 표시되는 배역 이름은 이해를 돕기 위한 비교 참조이며,
해당 작품이나 권리자와 아무 관계가 없습니다.

**이미지는 절대 사용하지 않습니다.** 배역의 이미지·초상·대사는
저작권과 초상권 대상이므로, 이름과 작품명 텍스트만 표시합니다.
서비스를 상업화할 계획이라면 상표권 검토를 별도로 받으시기 바랍니다.
견종 기질 묘사는 일반적으로 알려진 견종 특성을 참고한 비유이며, 성격 판정이 아닙니다.

### 럭키 가이드

저장된 사주와 **그날의 일진(日辰)**을 대조해 GO / STOP을 정합니다.
LLM 추론이 아니라 생극·합충 규칙에서 결정론적으로 계산하므로,
같은 사람 · 같은 날 · 같은 분야면 언제나 같은 결과가 나옵니다.

판정 요소
- 일진 천간·지지의 십성이 억부상 유리한지 (신강이면 덜어내는 쪽, 신약이면 돕는 쪽)
- 일진 지지와 내 일지의 합(合) · 삼합 · 충(沖)
- 일진의 오행이 원국의 부족한 기운을 채우는지, 과한 기운에 더 얹히는지
- 고민 분야별 십성 가중치 (일 / 연애 / 돈 / 소비 / 인간관계 / 건강)
- **행동의 방향** — 질문에서 취(取)·사(捨)를 판별해 반영

행동의 방향
같은 분야라도 "살까"와 "팔까"는 정반대 행동이므로 결과가 달라야 합니다.
명리에서 합(合)은 묶고 들이는 작용, 충(沖)은 흩고 내보내는 작용으로 보므로
이를 근거로 방향을 구분합니다.

| 방향 | 유리한 조건 |
|---|---|
| 들이기 (사다·시작·계약·고백) | 합·삼합, 신강한데 재성이 옴, 인성 |
| 내보내기 (팔다·정리·해지·이별) | 충, 식상, 신약한데 재성이 강함 |

방향 요소는 결론을 실제로 가르는 핵심이므로 다른 요소보다 비중을 크게 뒀습니다.
같은 날 "살까"와 "팔까"의 결론은 약 51% 확률로 갈리며, 합·충이 뚜렷한 날은 62%가 갈립니다.
나머지는 방향과 무관하게 그날 자체가 좋거나 나쁜 경우입니다.

일진은 60일 주기이므로 **60갑자 전체 점수의 중앙값**을 기준선으로 삼습니다.
그래서 특정 사주가 늘 GO만 나오거나 늘 STOP만 나오는 편향이 생기지 않습니다.
(20인 × 5분야 × 60일 = 6000건 검증 시 GO 51%)

출력은 아래 스키마를 그대로 따르며, 결과 화면에서 JSON 원본을 볼 수 있습니다.

```json
{
  "decision": "GO 또는 STOP",
  "decision_label": "...",
  "saju_reason": "...",
  "action_tip": "...",
  "lucky_item": "..."
}
```

나중에 LLM 백엔드를 붙이더라도 이 스키마 그대로 교체할 수 있습니다.
**단, LLM API 키는 브라우저에 두면 안 됩니다.** 정적 호스팅에서는 키를 숨길 수 없으므로,
LLM을 쓰려면 Supabase Edge Function 같은 서버 측 프록시를 거쳐야 합니다.

### 해석의 성격

원국 여덟 글자와 절기·대운 계산은 천문 데이터에 근거한 확정값입니다.
그러나 거기서 성향과 지향을 도출하는 부분은 검증된 인과관계가 아니라
전통 해석 체계입니다. 결정론적 단정을 피하고 구조적 경향성으로 서술했으며,
궁합 점수는 표준화된 공식이 아닙니다. 참고 자료로만 사용하세요.

## 6. 자주 나오는 오류

| 증상 | 원인과 해결 |
|---|---|
| `people 테이블이 없습니다` | `supabase/schema.sql`을 SQL Editor에서 실행하세요. |
| `권한이 없습니다` | RLS 정책이 안 만들어진 경우입니다. 스키마를 다시 실행하고 2-1의 확인 쿼리를 돌려보세요. |
| 로그인 링크를 눌러도 안 돌아옴 | 2-3의 Redirect URLs에 사이트 주소를 추가하세요. |
| `메일 발송 한도를 넘었습니다` | Supabase 기본 메일은 발송 한도가 낮습니다. 잠시 뒤 재시도하거나 익명 로그인 또는 자체 SMTP를 쓰세요. |
| 익명 로그인 오류 | 대시보드에서 Anonymous sign-ins를 켜야 합니다. |
| Pages에 옛 화면이 남음 | 브라우저 강력 새로고침(Ctrl+Shift+R). 배포 반영에 1~2분 걸립니다. |
